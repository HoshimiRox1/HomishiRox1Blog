# Roxy Blog Design System

> 本文件用于指导 Roxy Blog 后续页面开发。Home 是当前视觉母版，但不是所有页面的复制模板；Profile、Portfolio、Blog 应在同一视觉语法下，根据内容类型发展自己的版式人格。

## 1. 风格定位

Roxy Blog 的当前风格可以概括为：

**清爽新粗野主义 + 动漫角色舞台 + 海报式个人站。**

它不是传统博客首页、简历模板或营销落地页。第一眼应该有强烈的个人舞台感：冷白底、粗黑边、超大标题、密网格、糖果色导航色带、HUD 卡片、角色 cutout、底部滚动字幕和明确的分镜式动效。

后续页面必须遵循一个核心判断：

**全站共用 Home 的视觉语法，但每个页面根据内容类型组织自己的版式。**

统一的是风格语言，变化的是内容结构。不能把 Profile、Portfolio、Blog 做成 Home 换标题；也不能各做各的，导致像三个不同网站。

## 2. 设计原则

### 2.1 清爽新粗野主义

本项目里的新粗野主义不是脏乱、工业或纯硬矩形，而是：

- 粗黑边框和明确边界。
- 大字号、强字重、直接排版。
- 冷白底色和清爽 pastel 点缀。
- 少量硬阴影、错位、拼贴或信息标签感。
- 强结构、强节奏、强识别，而不是复杂装饰。

避免玻璃态、霓虹、柔和渐变、拟物阴影和过度精致的 SaaS 卡片感。

### 2.2 Home 是母风格，不是模板

Home 确立了全站的视觉语法：

- 冷白背景。
- 密网格辅助线。
- 粗黑边框。
- 超大海报标题。
- 右侧竖向色带导航。
- 圆角 HUD 信息模块。
- 底部 marquee。
- 角色舞台和滚轮唤醒。

后续页面应该继承这些语法，但版式需要服务具体内容：

- Profile 更像个人档案板或角色设定卡。
- Portfolio 更像作品展台或海报轮播。
- Blog 更像收藏库、书架或笔记索引系统。

### 2.3 圆角与硬矩形并存

大结构可以硬朗，例如右侧色带、底部 marquee、页面主标题、分隔栏。

内容模块可以圆角，例如 BGM、角色信息卡、标签、个人档案卡、作品信息条、博客分类卡。

圆角不是默认答案。判断标准是：如果元素承担结构和压场功能，优先硬朗；如果元素承载信息和交互，允许圆角 HUD。

## 3. 色彩系统

### 3.1 基础色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 主墨黑 | `#111111` | 粗边框、重要文字、底部 marquee、硬阴影 |
| 冷白 | `#F7FBFF` | 页面主背景 |
| 纸白 | `#FFFFFF` | 卡片、标签、HUD 模块底色 |
| 辅助灰 | `#434343` | 次级说明文字 |
| 网格线 | `rgba(17, 17, 17, 0.06)` | 背景结构线 |

### 3.2 页面识别色

| 页面 | 主色 | 深色 hover / 强调 |
| --- | --- | --- |
| Home | `#D8CCFF` | `#6B4DFF` |
| Profile | `#B9F5FF` | `#1494AB` |
| Portfolio | `#FFE7A6` | `#A07400` |
| Blog | `#C7F2D4` | `#2D7B4D` |

页面识别色主要用于导航色带、转场、局部标签、模块强调和页面专属状态。不要把整页铺成单一主色。

### 3.3 辅助强调色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 角色舞台粉 | `#FFD6E8` | 角色背板、视觉焦点 |
| 动作粉 | `#FF7AA8` | 播放按钮、主操作、局部强提醒 |
| 薄荷 | `#D7FFF1` | 状态、轻标签、清爽辅助区 |

### 3.4 色彩使用规则

- 黑白负责力量、秩序和可读性。
- Pastel 色负责页面识别、状态和情绪。
- 每个组件最多选一个主强调色，避免糖果色堆叠。
- 页面主色可以在局部重复，但不要形成单色主题页。
- 角色图颜色强时，背景色块要降权，优先保证角色清晰。

## 4. 版式与排版

### 4.1 标题

- 页面主标题使用超大字号、超粗字重、短词或全大写英文。
- 标题要像海报主视觉，不像普通页面 h1。
- 允许换行、错位、贴边或与网格形成强构图。

### 4.2 文案

文案应该短、硬、直接，接近舞台指令、标签或系统状态：

- `SCROLL TO WAKE THE STAGE`
- `ANIME / NOTES / WORK`
- `ROXY STAGE`
- `PROFILE INDEX`
- `WORK ARCHIVE`

中文说明可以存在，但不要变成大段正文堆在首屏。信息密度高的页面需要通过卡片、标签、编号和分区组织。

### 4.3 网格与边框

- 背景网格用于建立结构感，不应抢内容。
- 粗边框是全站最重要的视觉资产之一。
- 桌面端主结构边框可保持 `4px` 左右，小屏可降到 `3px`。
- 分隔线、色带边界、卡片边框应尽量统一黑色。

## 5. 可复用设计元素

### 5.1 右侧色带导航

右侧竖向色带是全站核心记忆点：

- 桌面端贯穿全高。
- 页面顺序固定为 Home、Profile、Portfolio、Blog。
- 使用页面识别色。
- hover 使用近白底和对应深色文字。
- 不保留当前页高亮，不加下划线，不做轻微漂浮。
- 转场以色带扩张和文字滑出为主，不使用普通淡入淡出。

### 5.2 HUD 卡片

HUD 卡片适合承载状态、说明、元信息和轻交互：

- 白底或浅色底。
- 粗黑边。
- 适度圆角。
- 短标题 + 简短说明或 meter / 标签。
- 可以使用硬阴影，但不要做柔光阴影。

### 5.3 标签和信息条

标签适合用于分类、状态、页面编号、技能、作品类型、博客分区：

- 胶囊或小圆角矩形均可。
- 文案短。
- 字重要高。
- 可以使用薄荷、浅青、纸白或页面主色。

### 5.4 Marquee

底部 marquee 是 Home 的压场元素，也可以在其他页面作为局部章节标题、滚动状态条或内容分隔使用。

使用时注意：

- 黑底白字最有力量。
- 不要每个区域都用 marquee，避免廉价化。
- 不要遮挡主要交互。

### 5.5 角色与视觉焦点

角色 cutout 是 Home 的强视觉内容。后续页面可以引用角色感、档案感、舞台感，但不一定每页都需要角色大图。

如果使用角色或头像：

- 图像必须清晰。
- 背板颜色服务角色，不抢角色。
- 元信息不要遮脸或遮关键轮廓。
- 动效要像入场、切换或翻页，不像普通滚动列表。

## 6. 页面方向

### 6.1 Home

Home 是全站第一视觉锚点：

- 海报级标题。
- 滚轮唤醒角色舞台。
- 右侧色带导航。
- 底部 marquee。
- BGM HUD。

后续不应随意削弱 Home 的冲击力。Home 可以继续作为风格校准标准。

### 6.2 Profile

Profile 应该像“个人档案板 / 角色设定卡”。

适合元素：

- 大号 `PROFILE` 标题和页面编号。
- 个人主档案卡。
- 头像、角色图或个人符号位。
- 技能 meter。
- 喜好标签。
- 联系方式和 GitHub 信息条。
- 时间线或状态栏。

Profile 可以更偏信息组织，但仍要保留舞台感和设定集感。不要做成普通简历页。

### 6.3 Portfolio

Portfolio 应该像“作品展台 / 海报轮播”。

适合元素：

- 大面积作品预览。
- 作品编号。
- 分类标签。
- 技术栈标签。
- 作品元信息条。
- 滚轮 wipe 或色块擦除切换。
- 单个作品占据主要视野。

Portfolio 可以比 Profile 更强动势、更强构图。它承载展示，不应该只是项目卡片网格。

### 6.4 Blog

Blog 应该像“收藏库 / 书架 / 笔记索引系统”。

适合元素：

- 博客笔记、番剧记录、电影记录、游戏记录四个主分区。
- 书脊、索引卡、收藏格、标签筛选。
- 阅读状态、评分、日期、分类。
- 稍高的信息密度，但边界必须清晰。

Blog 不应该只是文章列表。它应该像一个被设计过的个人收藏系统。

## 7. 动效规则

### 7.1 动效气质

动效应该是分镜式、舞台式、明确状态切换，而不是普通网页滚动。

优先使用：

- 色带扩张。
- 元素滑入。
- 作品 wipe。
- 标签或信息条 stagger。
- 角色入场。

谨慎使用：

- 透明度淡入淡出。
- 复杂连续滚动视差。
- 花哨弹性动效。

### 7.2 交互节奏

- 一次滚轮手势只触发一次明确切换。
- 动画期间需要锁定关键交互。
- 必须支持 `prefers-reduced-motion`。
- 动效完成后布局不能遮挡、跳变或残留错位。

## 8. 禁区

后续页面不要做：

- 普通博客模板。
- 普通简历模板。
- 营销落地页 hero。
- 大面积渐变背景。
- 玻璃态、霓虹、磨砂、柔光阴影。
- 随机 pastel 拼色。
- 所有模块都做成同一种卡片。
- 每个页面都复制 Home 的角色舞台布局。
- 各页面完全脱离 Home 风格自成一套。

## 9. 开发检查清单

新增或重做页面前，先检查：

- 是否继承冷白底、粗黑边、pastel 页面色、强标题和 HUD 语言？
- 这个页面有没有自己的内容人格，而不是 Home 换标题？
- 页面主色是否服务结构和状态，而不是大面积装饰？
- 信息是否通过编号、标签、卡片、分区或信息条组织？
- 动效是否是明确状态切换，而不是无意义装饰？
- 小屏是否保留可读性和可点击性？
- 是否避免遮挡 BGM、底部 marquee、导航和主要内容？
- 是否符合当前技术边界：Vite + React + GSAP + React Router + 普通 CSS / CSS Modules？

如果一个新页面的视觉方向明显偏离本文件，应先做小 mockup 或文字方案，与用户确认后再实现。
